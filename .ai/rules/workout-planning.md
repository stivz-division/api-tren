# Workout Planning

## WorkoutPlanning persistence and mutation locking
Хранить Eloquent-модели и реализации портов внутри WorkoutPlanning/Infrastructure, не связывая Domain с Laravel. Изменения расписания (create/update/delete) сериализуются Redis atomic lock по users.id; транзакции и уникальные ограничения БД остаются окончательной защитой. Программы удаляются физически, дочерние planned_exercises — каскадно.

## Общий транзакционный порядок для start, изменения плана и рекомендаций
После Redis mutation lock брать users.id FOR UPDATE и держать транзакцию через чтение и сохранение. Start, ручное изменение/удаление и применение рекомендаций используют общий user-row lock. Изменение целевого плана сохраняет устойчивый барьер ревизии даже при удалении/возврате упражнения; предложения других упражнений не устаревают без конфликта. Следующий новый запуск программы делает прежние proposed устаревшими.

## Несколько программ на день недели
День недели — признак группировки, а не идентификатор программы: одному пользователю разрешены несколько программ на один день, включая одинаковые названия. Weekday GET возвращает data-массив по id и 200 с пустым массивом; не выбирать первую программу неявно. Создание и перенос на занятый день допустимы; операции и интеграции адресуются ID программы. Это не отменяет правило одной активной тренировочной сессии.
